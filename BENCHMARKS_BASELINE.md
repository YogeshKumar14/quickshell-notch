## 1. Executive Summary

This baseline profile measures the memory footprint (RSS/VSZ), CPU utilization (idle vs. active audio visualizer playback), thread-level execution profile, and subprocess fork churn of the QuickShell notch system before any code optimizations.

### Key Baseline Findings
- **High Idle CPU Consumption**: QuickShell consumes **~9.4% – 10.0% single-core CPU** at idle (collapsed notch, no audio playing, no user interaction).
- **Idle Render Loop Repaint**: `QSGRenderThread` (TID 4799) is continuously active at **3.0% – 3.5% CPU** at idle due to an infinite 60 FPS opacity animation on the camera privacy indicator dot in `StatusBar.qml`.
- **Memory Footprint**: QuickShell daemon resident set size (RSS) is **385.34 MB** (394,588 kB) with a virtual memory size (VSZ) of **785.88 MB** (804,740 kB).
- **Zombie Visualizer / CAVA Leak**: CAVA (PID 5585) and Python streamer (PID 5576) remained actively running even when no media players were active (`playerctl -l` returned 0 players), accumulating **1m 08s+ CPU time** at idle (~1.0% constant CPU) due to missing `onObjectAdded`/`onObjectRemoved` lifecycle handling in the MPRIS player Instantiator.
- **Disk Polling Churn**: The visualizer streamer (`stream_audio_visualizer.py`) synchronously reads and parses `notch_settings.json` from disk every 10 frames (~333 ms at 30 FPS).
- **Subprocess Fork Churn**: QuickShell regularly forks background subprocesses at idle (e.g., `get_device_levels.py` every 12.0 seconds via `devicePollTimer`).

## 5. Background Subprocess Churn Observations

Real-time tracing of child process creations by parent PID `4607` over a 25.0-second monitoring window:

```
[  0.01s] Child PID 5576: /usr/bin/python3 /home/yogesh/.config/quickshell/scripts/notch/stream_audio_visualizer.py (persistent daemon)
[  7.56s] Child PID 81687: /usr/bin/python3 /home/yogesh/.config/quickshell/scripts/desktop/get_device_levels.py
[ 19.56s] Child PID 81811: /usr/bin/python3 /home/yogesh/.config/quickshell/scripts/desktop/get_device_levels.py
```

### Identified Churn Sources
1. **Periodic Device Polling (`get_device_levels.py`)**:
   - Triggered by `devicePollTimer` in `TopNotch.qml` (line 856).
   - Interval is exactly **12,000 ms** when notch is collapsed (drops to **2,000 ms** when expanded, OSD active, or audio menu open).
   - Each trigger forks a new Python interpreter instance (`/usr/bin/python3`), incurring OS process startup overhead, module loading, and `/sys`/`/proc` inspections.

2. **Visualizer Disk I/O Loop (`stream_audio_visualizer.py`)**:
   - In `main()` lines 228–230: every 10 frames (`frame_count % 10 == 0`), `get_bar_count()` opens and reads `notch_settings.json` from the filesystem.
   - At 30 FPS, this performs **3 disk reads per second** continuously while CAVA is running.

3. **MPRIS Instantiator Lifecycle Zombie Leak**:
   - In `TopNotch.qml` (line 1010), `Instantiator { model: Mpris.players }` binds property change listeners to players but does not handle `onObjectAdded` and `onObjectRemoved`.
   - When media players stop or unregister, `root._mprisTrigger` is not recalculated, leaving `isPlaying` in a stale state and preventing the visualizer process from tearing down cleanly.

4. **MediaController Playerctl Fork Loop**:
   - `MediaController.qml` contains `posPollingTimer` (line 465) running every **500 ms** whenever `root.isPlaying` is true, invoking external `playerctl position` CLI command.
   - Polling is not gated on notch visibility, continuing even when the notch is completely collapsed.

## 7. Next Optimization Targets (Milestones M1 & M2)

| Target ID | Problem | Proposed Optimization | Target Impact |
|---|---|---|---|
| **OPT-01** | Infinite 60 FPS camera dot animation | Gate animation so it only runs when camera is active or when expanded; disable continuous idle looping | Reduce QuickShell idle CPU by ~3.0% – 3.5% |
| **OPT-02** | Zombie visualizer & CAVA idle run | Add `onObjectAdded`/`onObjectRemoved` to MPRIS Instantiator; throttle CAVA when silent | Eliminate 1.0% idle CPU and CAVA daemon leak |
| **OPT-03** | Visualizer 333 ms disk polling | Cache bar count in memory; reload on IPC or inotify signal only | Eliminate 3 disk I/O operations per second |
| **OPT-04** | Subprocess fork churn (`get_device_levels.py`) | Optimize device level polling, batch reads or use persistent daemon/signals | Eliminate frequent Python process forks |
| **OPT-05** | MediaController 500 ms `playerctl` fork | Gate `posPollingTimer` on `root.isExpanded && root.currentPage === 0` | Eliminate 2 forks/second when collapsed |
| **OPT-06** | Canvas & OpacityMask repaints | Cache SVG textures, replace software 2D Canvas repaints with hardware primitives | Lower memory and animation jitter |
